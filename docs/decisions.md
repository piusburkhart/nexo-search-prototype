# Decisions & assumptions

| # | Topic | Conflict / gap | Decision |
|---|-------|----------------|----------|
| D1 | Data path | Brief says `src/data/mock-data.json`; file was at `src/mock-data.json` (untracked). | Moved to `src/data/mock-data.json`. |
| D2 | `docs/` | `docs/` and `docs/screens/*.png` did not exist. Only CLAUDE.md exists. | Exported reference frames myself from Figma (`docs/screens/`), stored at 1x (402x874) because the MCP screenshot tool returned 1x. Visual diffs compare at 1x. |
| D3 | Stack | CLAUDE.md: Vite + React + TS + Tailwind v4. | Used. Design tokens live as CSS variables in `@theme` (Tailwind v4), so utilities map to tokens. No hardcoded colours in components. |
| D4 | Figma content vs data | Figma shows placeholder copy (Ana, Lisa, "Swarovski Optik", "Actions", folder "Lantern 30"). Data says Elin, Priya, Jonas... | mock-data.json wins on content; Figma wins on layout/visuals. |
| D5 | Actions | Figma has an "Actions" filter tag and action rows (todo, mail). mock-data.json has no actions. | Not built (no data; would need invented content). Tag set is Meetings / Memos / Transcript (+ date tags). |
| D6 | Grouping | Figma shows tag suggestions ('Actions 4, Folder 1, Recording 8') stacked in one card; brief wants grouped results with counts. | Result list is grouped by type with counts. The same groups (Meetings, Memos, Transcript) are the stacked suggestion card. Typing a partial word after a space (e.g. `Lantern tr`) narrows the card. Picking a tag writes its word into the text (completing a partial word), shown with a grey background; the word is not a search term. Several tags combine; deleting the word removes the tag. |
| D7 | Folders | Figma shows a "Folders" section in search with a "Lantern" folder (count). | The one project in data (Project Lantern) is the folder; count = recordings with that projectId. Tapping it filters to the project. Shown only when the query is empty, as in Figma. |
| D8 | Date tags | Figma recognises dates and offers a date pill with a count. Owner also asked for year filters. | Recognised: `dd.mm.yy`, `yyyy-mm-dd`, `d Mon yyyy`, `Month yyyy`, a bare month name (assumes the newest year in the data, 2026), and a bare year (`2026`). Offered as a pill; picking it filters to that day/month/year and hides the pill (date text stays in the input as in Figma). Exact days are never search terms; months/years are plain terms until applied. `16 October` stays plain text, bare `may` is ignored. |
| D9 | AI search | Figma shows a "AI Synthesis" pill, a "Synthesizing for you" state and a result paragraph. No LLM allowed. | Offered when query has 3+ words or ends with "?". Synthesis is a deterministic extractive summary built from top hits (mock "thinking" delay ~900ms). Content cards below reuse transcript hit cards, as in Figma. |
| D10 | Missing screens | Figma has no meeting detail, memo detail or transcript screen, though the brief requires "opens the transcript at the segment". | Built simplest versions in the design system: Meeting detail (summary, participants, transcript link), Memo detail, Transcript (segments, highlight, find-in-transcript with count + prev/next). Logged as invented. |
| D11 | No-results state | Not in Figma. | Simple empty state: "No results for “x”" with hint. |
| D12 | Fonts | Figma uses Brown (sans) and Test Domaine Text (serif), both licensed. | Fallbacks: system sans for Brown, Georgia for Domaine. Tokens named `--font-sans`/`--font-serif` so they can be swapped. |
| D13 | Home chips | Figma chips: All, Meetings, Memos, Folders, People; no behavior notes for the last two. | All, Meetings, Memos filter the feed. Folders and People are rendered for fidelity but do nothing (no screens in Figma). |
| D14 | Keyboard | Figma draws an iOS keyboard. | Not drawn; the real keyboard / none on desktop. Search bar docks to bottom of the phone frame. |
| D15 | Viewport | Figma is a 402x874 mobile frame. | App renders in a 402-wide column, centered with a phone-like frame on larger screens; full-bleed below 402px. Tests use 402x874. |
| D16 | Multi-word | "Multi-word queries match all words." | Each word must appear somewhere in the same item (title+body), any order. |
| D17 | Transcript meetings | Only 3 of 10 meetings have transcripts. | Others open without a transcript link. |
| D18 | Memo kind | Brief says 7 work, 3 personal; no explicit field. | Personal = memo has tag `personal` (memo03, 04, 08). Shown identically in results, per brief. |

| D19 | "New" | Figma shows a "New" tag/section; no rule given. | New = within 7 days of the newest recording (deterministic, no clock). Older items go under "Earlier" without a tag. |
| D20 | Find count | "match count" in transcript. | Counts matching segments (all words must appear in a segment), shown as "n / total"; next/previous wrap around. |
| D21 | Environment | `node_modules` had a broken partial install (vite/rolldown without dist). | Reinstalled with `npm ci`. Added `@playwright/test` (needed for the required tests) and `npm test`. |
| D22 | Search bar position | Figma docks the bar above the iOS keyboard. | Docked to the bottom of the phone frame; no fake keyboard (D14). |
| D23 | Tab bar | Figma "Actions" tab goes to an Actions screen that is out of scope (D5). | Tab rendered, inert. |
| D24 | Mobile | Brief is a 402px phone design; the real phone has its own status bar and keyboard. | Below 640px the fake status bar is hidden (safe-area top padding instead) and the app is fixed full-screen. Tapping search focuses a hidden proxy input inside the tap so iOS opens the keyboard, then the real field takes focus. The search bar sits directly above the keyboard using the visual viewport (`--kb`). Inputs are 16px to avoid iOS zoom. |
| D25 | iOS form bar | Safari shows a system bar (up/down arrows, checkmark) above the keyboard. | Cannot be removed from a web page. Only a native app or a different input mechanism could avoid it; not attempted. |
| D26 | Results are display-only | Brief said a transcript hit opens the transcript at that segment. Owner later asked: no jump from a search result to the transcript / meeting / memo. | Cards inside Search (results, idle recordings, AI content cards) are not links and show no arrow. Transcript / meeting / memo screens remain reachable from Home and each other. The transcript still opens at a segment via `#/transcript/:id?seg=<seconds>&q=` (tested by direct link). |
| D27 | Keyboard | Tapping a suggestion blurred the field and closed the keyboard. | Suggestions (tags, date, AI) do not take focus and refocus the field; the keyboard closes only on pointer-down/scroll in the results area. |
| D28 | Dock position | Search bar floated ~40pt above the keyboard on iPhone. | `--kb` is now measured against the frame the bar is positioned in, not `window.innerHeight`. Unverified on device. |
| D29 | Tag autocomplete | Tags must complete the word being typed. | The last word is "partial" while it is a prefix of an unselected tag word (`transcr`); suggestions narrow to matching tags and picking one replaces the partial word. The partial word is not a search term; with no other terms the idle view stays (no "no results"). A tag-only query (`transcript `) lists everything of that type; tag counts then show the whole corpus. |
| D30 | Keyboard layout | Keyboard pushed results up; bar too high. | On phones the frame is translated by the visual-viewport pan so content does not move; `--kb` = frame height minus visual viewport height; bar padding is a CSS variable (8px with keyboard, safe-area otherwise). Safe-area padding was the likely cause of the gap. Unverified on device. |
| D31 | Status bar colour | Browser status bar showed a different grey. | `theme-color` meta, html and body background follow the current screen (gray-200 on Home, gray-50 elsewhere). |
| D32 | Password | Owner asked for password protection with password "above". No backend allowed. | Client-side gate: SHA-256 of the password is compared in the browser; success is remembered in localStorage. This keeps casual visitors out but is not real security (the app code and mock data are still downloadable). Real protection would need Vercel Deployment Protection on the owner's own account. |
| D33 | AI offer | AI Synthesis only when keyword search cannot answer. | Offered when there are no keyword results, or the query looks like a question (ends with `?`, 4+ words, or starts with a question/request word). Starting it closes the keyboard; with no relevant transcript content it answers "Can’t help you with that." |
| D34 | Search default | Default search view must be empty. | Only the "Ask about anything." prompt remains (kept from Figma); folders and recent recordings are removed. Content appears once you type. |
| D35 | Status bar | iOS 26 tints the status bar from the fixed element at the top. | A fixed strip of the screen's colour sits behind the status bar (mobile only) and theme-color is replaced per screen. |
| D36 | Search bar chrome | Filter icon and the faded backdrop behind the bar were removed. | Small clear (x) button appears when the field has text and clears text, tags and date. The bar has a stronger drop shadow; the dock is transparent and click-through. |
| D37 | Status bar | Colour stayed stale after leaving Home. | One persistent fixed strip at the top whose colour follows the screen (not re-created per screen), plus theme-color and html/body background. Unverified on device. |
| D38 | Shadow line above keyboard | A hard line appeared under the search bar where its shadow met the keyboard. Pixel check on the screenshot: shadow tint of ~3 levels stops abruptly at the bottom edge of the web view (iOS clips the page there). | Search bar, tag card, date pill and AI pill share one shadow (`--shadow-bar`) that is lifted upward and has almost no extent below, so nothing is left to clip. Unverified on device. |
| D39 | Suggestions follow the keyboard | Suggestions stayed when the keyboard was dismissed. | Tags, date pill and AI pill show only while the search field has focus. Enter / the iOS search key blurs the field (closes keyboard and suggestions); results stay. Tapping a suggestion does not blur (mousedown is prevented). |
| D40 | No scrolling on the bar | Dragging on the bar or suggestions scrolled the page and stuttered. | `touch-action: none` on the bar and suggestions, `overscroll-behavior: none` on html/body. |
| D41 | Memos have no headline | Memo title was shown in search results and on the memo screen. | Memos show only their body everywhere (Home, search, detail); memo titles are not shown or searched, only the body is. Related-memo links use the body text. |
| D42 | Meeting = transcript | A meeting and its transcript are one thing; transcript search is deep content search, not file browsing. | A meeting is a hit if its title/summary or any transcript moment matches, and matching moments (speaker, time, text) are nested under the meeting card. The Transcript tag switches to the deep view: a flat list of moments, each showing its meeting. Only 3 of 10 meetings have transcript text in the data (brief), so the others match on title/summary; no transcript text was invented. |
| D43 | One type at a time | After choosing Transcript, Meetings/Memos should not be suggested. | Type tags (Meetings, Memos, Transcript) are mutually exclusive: once one is chosen no type is suggested. Date tags are separate. |
| D44 | Static content | Content moved when the keyboard opened/closed. | The results area has a fixed bottom padding (no dependence on keyboard height); the keyboard, bar and suggestions hover over it. |
| D45 | Hovering elements | Shadow was too strong. | Bar, close button, suggestion card and AI pill: 1px gray-200 border and a very light shadow (`0 2px 10px rgba(0,0,0,.05)`). Replaces D38. |
| D46 | Dates as tags | Typing `2026` showed "No results" and a small pill. | A recognised date (day, month or year) is never a search word. It is offered as a row (calendar icon, label, count) in the same suggestion card as the type tags; selecting it filters and gives the typed date text the grey tag background. |
| D47 | Content moved with the keyboard | iOS slides the page up when the focused field would end up under the keyboard; the old correction (translating the frame afterwards) lagged, so content visibly moved. | The correction is removed. Instead, the search bar is moved to where the keyboard will end *before* focus (on the Home search tap and on touching the field), so iOS has nothing to reveal and does not slide. The keyboard height is remembered (first guess: 45% of the screen). If the page is scrolled anyway it is put straight back. Unverified on device. |
| D48 | Suggestion rules | Suggestions offered things that did not help. | (1) While a word is being typed, only completions for it are suggested: a type it starts (`tr` -> Transcript) or a date it could become (`20` -> 2026, `sep` -> September 2026, a full date as typed). Picking one replaces the word. (2) Otherwise a type tag is only suggested when the results contain at least two types; a typed but unselected date is suggested too. (3) AI Synthesis appears whenever there is no other suggestion, when nothing is found, or for question-like queries. |
| D49 | Tap back into the field | After blurring (scrolling the results) and tapping the search field, the bar jumped up but no keyboard appeared. | The bar used to move on touch-start, so it slid out from under the finger and the tap never reached the field. Now the tap (touch-end) moves the bar and focuses the field in the same gesture, which opens the keyboard. |
| D50 | Fragments | Typing `n` suggested all three types. | A word still being typed only gets completions (`m` -> Meetings, Memos). A fragment under 3 letters that completes to nothing suggests nothing (AI Synthesis may show as the fallback); from 3 letters it counts as a word and gets the normal suggestions. |
| D51 | Full dates | A full date expanded to "2 Oct 2026" and wrapped to a second line in the suggestion. | A typed day keeps its typed format (`02.10.26`) in the suggestion and in the input; the suggestion card grows with its label and never wraps. |
| D52 | AI Synthesis is always there | Figma 75:3668 (supersedes D33): the AI button is a permanent control, not a contextual suggestion. | A 40x33 pill with a sparkle sits at the top of the search results (44px under the status bar, as in Figma) on every state of the screen, including empty. The suggestion card no longer contains it. Search results stay on screen the whole time. |
| D53 | AI states | Figma shows four states: disabled (`De`), ready, thinking, answer. | Disabled (gray-300) until the search words are 3+ characters, or a date/type tag is chosen; ready (gray-975); thinking (three dots in the button plus "Synthesizing your answer…", the Figma copy "Synthezising" was a typo); done (answer grows out of the button and pushes the results down). Tapping the button again in the done state hides the answer. It still runs when keyword search finds nothing and then says "Can’t help you with that." Starting it closes the keyboard. |
| D54 | Answer content | Figma answer is prose with time chips (mic + mm:ss). No LLM allowed. | Extractive: a lead sentence plus up to three transcript sentences from the best-matching moments, each followed by a chip with its time. Chips are not links (D26). |
| D55 | Token | Figma uses #D9D6D4 for the disabled button. | Added `--color-gray-300`. |
